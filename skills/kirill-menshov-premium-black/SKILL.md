# Презентация в формате Kirill Menshov Premium Black

Персональная дизайн-система презентаций Кирилла Меньшова: ночная сцена, тёплая палитра, фотографии песка и камня как иллюстрация, схемы из тех же токенов, одна анимация - живая световая линия, строгая типографика. Скилл не рисует слайды свободно: он переводит содержание в JSON-спецификацию из каталога раскладок и собирает её детерминированным скриптом. Так любая ИИ-система даёт один и тот же визуальный результат.

Автор оригинала - Кирилл Меньшов (версия 2.3.2). Это адаптация для OuroborosHub: дизайн, раскладки, шрифты и фотографии оригинальные, изменены сборка, рендер и безопасность (`CHANGELOG.md`, авторство и лицензии - `NOTICE.md`).

*In English:* this skill builds Russian-language decks in the author's fixed design system. The agent writes a JSON spec, `scripts/build_deck.py` turns it into a single-file HTML (fonts and photos embedded, no network requests), PNG slides, a PDF and an editable PPTX. PNG, PDF and PPTX need a one-time `scripts/setup_renderer.py install` (about 105 MB) into the skill's own state folder.

## Когда использовать

- Пользователь просит презентацию, слайды, деку, питч, доклад для правления или совета директоров
- Пользователь просит перевести документ, заметки или таблицу в слайды «в нашем стиле» или в стиле Premium Black
- Не использовать для документов A4 и whitepaper и для правки готовых PPTX

## Запуск в Ouroboros

Все команды - `skill_exec(skill="kirill-menshov-premium-black", script=..., args=[...])`.

1. Только при первом PNG, PDF или PPTX: `script="scripts/setup_renderer.py", args=["status"]`. Если `"status": "missing"`, выполни `args=["install"]` (около 105 МБ, один раз; сначала установщик Playwright, при недоступном CDN та же сборка из официального хранилища Google Chrome for Testing), затем `args=["check"]`. Браузер ставится только в папку состояния скилла. Для одного HTML браузер не нужен.
2. Положи `spec.json` в рабочую папку задачи (или в загрузки) и собери: `script="scripts/build_deck.py", args=["<путь к spec.json>", "--render", "--pdf", "Deck Name v1.pdf"]`. Для PowerPoint добавь `"--pptx", "Deck Name v1.pptx"` (тогда PNG, PDF и PPTX будут в одной папке задания). Свои фотографии добавь каждой отдельной парой `"--photo", "имя=<путь>"` (см. «Фотографии пользователя»). Образцы собираются по относительному пути `assets/example_spec.json`.
3. Ответ заканчивается JSON: `job_dir` - новая папка `<state>/outputs/<задание>/`, `files` - пути к HTML, PDF, PPTX, архиву шрифтов и папке `png/`, `warnings`. Отдай файлы пользователю через `send_file`; ссылки на скачивание не составляй.

Коды выхода: 0 готово; 2 гигиена текста; 3 поле или значение не из каталога; 4 нет браузера рендера (HTML при этом собран, выполни шаг 1); 5 отклонённый путь, адрес или имя файла.

Что получает пользователь и что откроется на другой машине без сети:
- HTML - один файл: CSS, шрифты, фотографии и кадры линии вшиты, внешних ссылок нет (их запрещает Content-Security-Policy). Весит 1-12 МБ в зависимости от числа фотографий. С `--gif` живая линия в HTML ещё и движется (плюс 3-6 МБ на слайд)
- PDF - картинки слайдов (JPEG 95), `--pdf-lossless` даёт пиксельно точный и в несколько раз более тяжёлый файл
- PPTX - фон слайда картинкой и редактируемые текстовые блоки, включая подписи схем-графиков: подписи осей `curve` и подпись/процент кольца `ring-bars` остаются текстом, а не пикселями фона. Рядом `<имя> fonts.zip`: шесть TTF и их лицензии; отдай архив вместе с PPTX и попроси установить шрифты на машине, где открывают файл (без них текст редактируется, но PowerPoint подставит другой шрифт)

## Рабочий процесс

1. Прочитай `references/text-standard.md` и `references/layouts.md`. Если в исходнике есть рисунки, схемы или фотографии, также `references/images.md`. Для оценки визуала или спорных случаев `references/design-tokens.md`.
2. Собери содержание: вывод деки одним предложением, 2-4 главы, в каждой тезисы и числа с источниками. Порядок материала пользователя сохраняй. Аудитория по умолчанию правление, 10-14 слайдов; стратегическая сессия 16-24. Перечисли все рисунки исходника и для каждого реши по таблице из `references/images.md`: схема (раскладки `flow`, `layers`, `cycle`, `matrix`, `tree`, `compare`, `funnel`, `loop`), данные или фото. Схему никогда не сворачивай в текстовые карточки и не вставляй картинкой.
3. Напиши `spec.json` в рабочей папке задачи: корень `brand`, `meta`, `doc_title`, массив `slides`. `brand` - метка в левом верхнем углу каждого слайда: короткое имя презентации, программы или проекта до 32 знаков («Стратегия ИИ · 2027», «Платформа данных»), не имя автора и не название шаблона. Для каждого слайда выбери раскладку из каталога, заполни только её поля (чужие поля останавливают сборку с кодом 3). Капсулы `pill` до 28 знаков, крупные числа `num` до 12 знаков: длиннее сборщик уменьшит сам, но это заметно хуже. Структура: `title`, затем один слайд с главным выводом, далее `section` на каждую главу, завершение `cards` с одной карамельной карточкой или `statement`, финал `thanks`. Образец всех раскладок: `assets/example_spec.json`; образец схем и живой линии: `assets/example_schemes_spec.json`.
4. Прогони чек-лист из `references/text-standard.md`: заголовки-утверждения, «мы», ИИ кириллицей, только дефис `-`, ни одного восклицательного знака, у слайдов с данными заполнен `foot` с источником.
5. Собери и отрендери (раздел «Запуск»): `build_deck.py spec.json --render --pdf "Deck Name v1.pdf"`. Код 3 - поля или значения не из каталога, код 2 - нарушение гигиены текста; исправь спецификацию, не используй `--allow-hygiene`. Предупреждения `WARN` про длину тоже исправь текстом, а не надейся на автоподгонку.
6. Открой PNG из папки `png/` задания и проверь каждый слайд: обрезанные слова в карточках, заголовок длиннее двух строк, пустые зоны больше трети слайда, нечитаемый текст на фото, больше одной карамельной карточки или медной капсулы. Исправь текст или смени раскладку, пересобери (каждая сборка - новая папка).
7. Отдай PDF (и HTML по запросу). Если нужен PowerPoint, добавь `--pptx "Deck Name v1.pptx"`: скилл сам соберёт редактируемый PPTX и архив шрифтов. Никогда не перерисовывай слайды в PPTX вручную или другим инструментом. Имя файла английскими словами с пробелами и версией: `AI Delivery Strategy v1.pdf`; в сообщении кратко назови структуру деки и одно место, где пользователю стоит проверить цифры.

Готово, когда PDF собран без предупреждений сборщика, все слайды просмотрены глазами, а число слайдов и порядок глав совпадают с согласованным содержанием.

## Что нельзя менять

- Палитра: эспрессо, какао, мокко, карамель, латте, слоновая кость, плюс медь как второй акцент и графит как служебный. Никаких других цветов, включая зелёный и красный для динамики
- Фотографии из `assets/photos/`; файлы пользователя и сгенерированные кадры только через `scripts/tone_photo.py` и промпт из `references/images.md`, и в сборку они попадают только явной передачей `--photo` (см. ниже). Иконки, 3D-объекты, эмодзи, чужие растровые схемы не используются
- Анимация одна - живая световая линия (`loop`, по запросу `flow` и `cycle`), не больше двух слайдов на деку. Переходы, появления и другие эффекты PowerPoint не добавляются
- Если у слайда есть `day: true`, анимация на нём не рисуется: линия рассчитана на тёмную сцену. Отчёт сборки пишет об этом в `warnings` - не оставляй такое предупреждение без решения (убери `day` или `anim`)
- Шрифты Unbounded и Inter из `assets/fonts/`. Нумерация карточек только визиром с медной риской
- Раскладки только из каталога: не писать свой HTML и не править `assets/deck.css` под отдельную деку. Если содержание не ложится в каталог, разбить на два слайда или упростить
- Медная капсула одна на слайд, карамельная карточка одна на слайд, фотокарточек не больше трёх, кроме раскладок `five` и `team`

## Поля спецификации, которые чаще всего забывают

- `brand` в корне - имя презентации или программы для левого верхнего угла. Без него сборщик берёт `doc_title` и предупреждает
- `eyebrow` описывает жанр и раздел слайда («Данные · 2026», «Раздел 02 · Экономика»), не повторяет заголовок и не содержит имени шаблона
- `[[текст]]` в заголовке красит бронзой вывод, не произвольное слово. Одна вставка на слайд
- `\n` переносит строку в заголовках и метках
- `pill` на уровне слайда рисует медную капсулу в футере (дата на титуле). Капсула внутри карточки задаётся в элементе `items[].pill`
- `focus: "50% 30%"` кадрирует фото, когда горизонт или гребень попадает под текст

## Фотографии пользователя

- Ключ библиотеки (`"dunes-mist"`) - первый выбор
- Свой снимок проходит два шага. Шаг 1 - тонировка: `tone_photo.py <файл> <имя>.jpg`, файл из папки задачи или загрузок. Скрипт возвращает фактический абсолютный путь в `file`, свободное имя для поля `photo` в `spec_value` и готовую пару аргументов в `build_args`. Шаг 2 - объявление в сборку: передай `build_args` как два отдельных аргумента (`"--photo"`, `"имя=путь"`), а в `photo` укажи ровно `spec_value`. Не подставляй вместо returned path предполагаемый относительный файл. Без `=<путь>` именем становится базовое имя файла
- Путь в самой спецификации - не разрешение читать файл: без объявления `--photo` сборка отклонит его с кодом 5. Никаких общих папок-разрешений нет: читаются только библиотека и файлы, явно переданные оператором в эту сборку, и имя в `--photo` всегда идёт с полным путём к выбранному файлу (для затонированного - путь из поля `file` ответа `tone_photo.py`)
- Принимаются JPEG, PNG и WebP. Адреса `http(s)` отклоняются и в `photo`, и в `--photo` до любого чтения; имя не должно совпадать с ключом библиотеки. Снимок перекодируется: EXIF, ICC, XMP и JPEG-комментарий в деку не попадают, доходит только картинка

## PPTX

`--pptx "Name v1.pptx"` использует тот же рендер. Рендер делает два снимка каждого слайда: полный и без текста, и снимает с DOM геометрию всех текстовых блоков. PPTX получает фон без текста (карточки, фото, свечение, зерно, плашки, линии, иконки) и поверх - текстовые блоки с теми же координатами, кеглем, начертанием, цветом и разрядкой: заголовки, числа, подписи и текст капсул редактируются в PowerPoint. Бронзовый градиент заголовков в PPTX на ночном слайде становится латте `#DCC8A8`, на дневных светлых карточках - тёмной бронзой `#A67C3F`.

- Шрифты: python-pptx не умеет встраивать их в файл, поэтому рядом с PPTX появляется `<имя> fonts.zip` (Inter Light, Inter, Inter Medium, Inter SemiBold, Unbounded Medium, Unbounded SemiBold и лицензии SIL OFL 1.1). Без установленных шрифтов PowerPoint подставит свои, и переносы строк сдвинутся
- `--flat` кладёт на каждый слайд полный снимок без редактируемого текста: пиксельно точный вариант для рассылки (архив шрифтов не нужен)
- Масштаб `--scale 2` даёт фон в удвоенном разрешении, файл в четыре раза тяжелее
- Проверка: открой PPTX или сконвертируй в PDF и сравни с PNG из `png/`; допустимы только разные переносы в длинных заголовках
- Живая линия в PPTX - GIF; PowerPoint проигрывает его в показе слайдов

## Окружение

- Права скилла: `subprocess` (скрипты сборки и рендера), `net` (разовая установка браузера рендера), `fs` (чтение спецификации и своих снимков, запись в папку состояния и папку задания). Декларация `fs` описывает фактические файловые операции, а не песочницу: границы чтения и записи задаёт код сборки.
- Ouroboros ставит пакеты из `install_specs` (numpy, Pillow, python-pptx, Playwright 1.65.2) в изолированное окружение скилла при включении. Глобальные пакеты, npm и Node не нужны
- Браузер рендера - headless shell Chromium той сборки, что закреплена в Playwright 1.65.2 (Chrome for Testing 159.0.8154.6). `setup_renderer.py install` кладёт его в `<state>/ms-playwright`; системный Chrome, общий кэш Playwright и профили браузеров не используются. Удалить: удалить эту папку
- Рендер всегда запускает браузер с включённой песочницей Chromium, временным профилем и без доступа к связке ключей, в офлайн-режиме; все запросы, кроме файла деки, блокируются и перечисляются в `outside_requests` отчёта (норма - пустой список). Отключить песочницу нельзя: если закреплённый браузер не запускается, PNG, PDF и PPTX не собираются (код 4), а HTML остаётся доступен
- На Linux браузеру нужны системные библиотеки Chromium; скилл их не ставит. Для Linux arm64 сборки в хранилище Google нет: там работает только CDN Playwright
- Одна команда `skill_exec` ограничена 300 секундами. 24 слайда с PPTX собираются примерно за 40 секунд; первая генерация GIF живой линии добавляет 5-10 секунд на слайд, дальше кадры берутся из кэша `<state>/cache/anim/`

## Типичные сбои

- Сборка остановилась с «Гигиена текста не пройдена» - в спецификации тире, восклицание или латинское AI. Исправь текст
- «Фотография не найдена» - ключ не из библиотеки; ошибка печатает доступные ключи. Свой снимок передавай парой `"--photo", "имя=<полный путь к выбранному файлу>"` и этим же именем в поле `photo`
- Код 5 «внешние адреса не поддерживаются» - в `photo` или `--photo` попал адрес `http(s)`; сборка не ходит в сеть
- Код 5 «путь в спецификации - не разрешение на чтение файла» - снимок не объявлен в этой сборке: добавь пару `"--photo", "имя=<полный путь к выбранному файлу>"` (для затонированного - путь из поля `file` ответа `tone_photo.py`) и укажи `имя` в поле `photo`
- Код 3 со словами `kind`, `focus`, `widths` или «нужно число» - значение не из каталога: `kind` из `ink | glass | caramel | photo`, `focus` вида `"50% 30%"`, `widths` вида `["2fr", "1fr"]`, числа без единиц
- Код 4 «браузер рендера не запустился» - выполни `setup_renderer.py install`, затем `check`. HTML к этому моменту уже лежит в папке задания
- Заголовок карточки обрезан справа - слово длиннее 12 знаков в раскладке на четыре карточки; перейди на три карточки или замени слово
- Текст капсулы или число шире карточки - сборщик измеряет текст по метрикам шрифтов (`assets/font_metrics.json`) и записывает в HTML явные `font-size` и `width`: капсула сжимается до 12px, затем переносится на две строки; число уменьшается до половины кегля. Если в PNG капсула двухстрочная, сократи её до 2-3 слов («Этап 04 · Риски» вместо «Этап 04 · Согласование с комитетом по рискам»)
- Слайд собрался пустым или без части содержимого - поле названо не так, как в каталоге; сборщик останавливается с кодом 3 и печатает допустимые поля раскладки
- Слайд с данными выглядит пустым - в `kpi` или `year-kpi` не заполнены `label` и `delta`; каждому числу нужны метка и динамика
- Текст на фото не читается - смени `focus` или возьми контрастный кадр (`dunes-mist`, `dune-night`, `canyon-light`)
- Схема из исходника превратилась в карточки с текстом - рисунок не был учтён на шаге 2; вернись к таблице в `references/images.md` и выбери раскладку-схему
- PPTX с живой линией весит больше 15 МБ - анимированных слайдов больше двух; оставь `anim` только там, где линия несёт смысл
- Живая линия не двигается - в PDF и в режиме редактирования PowerPoint это нормально, GIF играет в показе слайдов; в HTML анимация видна, если собрать с `--gif`

## Версионность

Версия хранится в трёх местах и должна совпадать: `version` в этом файле, `VERSION` в `scripts/premium_common.py`, последняя запись в `CHANGELOG.md`. Сборщик печатает версию при каждом запуске и предупреждает о расхождении; `build_deck.py --version` выводит её вместе с версией оригинала. Собранный HTML несёт версию в `<meta name="generator">` и `data-skill-version` на `body`.

Схема оригинала `MAJOR.MINOR.PATCH`, суффикс `-hub.N` - номер адаптации для OuroborosHub:
- `PATCH` - исправление дефекта рендера или текста без изменения полей спецификации (старые `spec.json` собираются без правок)
- `MINOR` - новая раскладка, новое необязательное поле, новая фотография, новое предупреждение
- `MAJOR` - изменение палитры, шрифтов, удаление или переименование полей и раскладок; старые спецификации требуют правки

При любом изменении обнови три места выше, опиши изменение в `CHANGELOG.md` одной-тремя строками (что было не так, что сделано, как проверено), пересобери оба образца, просмотри все PNG и прогони `tests/test_premium_black.py`.

## Файлы скилла

- `scripts/build_deck.py` - спецификация → HTML (+ `--render` → PNG и PDF, `--pptx`), проверка полей и значений по каталогу, гигиена текста, подгонка капсул и чисел по метрикам шрифтов, папка задания и отчёт
- `scripts/render_deck.py` - рендер слайдов в PNG браузером Playwright; для PPTX также фон без текста и `geometry.json`
- `scripts/build_pptx.py` - PNG + геометрия → редактируемый PPTX (`--flat` для плоского), GIF между фоном и текстом, архив шрифтов
- `scripts/setup_renderer.py` - установка и проверка браузера рендера
- `scripts/schemes.py` - восемь раскладок схем; `scripts/particle_path.py` - живая линия (кадр PNG и GIF по форме пути)
- `scripts/tone_photo.py` - тонировка своего снимка под библиотеку; `scripts/premium_common.py` - пути, версия и правила записи
- `assets/deck.css`, `assets/fonts.css`, `assets/fonts/` - дизайн-система и шрифты с лицензиями; `assets/fonts/ttf/` - статические TTF для машины, где открывают PPTX
- `assets/font_metrics.json` - ширины глифов Inter и Unbounded для расчёта без браузера
- `assets/photos/` - 23 снимка библиотеки, `assets/example_spec.json` - образец на 24 слайда, `assets/example_schemes_spec.json` - восемь схем (условные данные)
- `references/layouts.md` - каталог раскладок и поля, `references/design-tokens.md` - токены и лимиты, `references/text-standard.md` - текстовый стандарт и чек-лист, `references/images.md` - решения по рисункам исходника, промпт генерации, живая линия
- `tests/test_premium_black.py` - проверки сборки, путей, значений и рендера
- `NOTICE.md` - авторство, лицензии шрифтов, сведения о фотографиях; `CHANGELOG.md` - история версий
