# Изображения и схемы

Скилл не превращает рисунки исходника в текст и не вставляет чужие картинки как есть. Для каждого рисунка, схемы, диаграммы и фотографии из исходного материала на этапе разбора принимается одно из трёх решений, и оно записывается в спецификацию.

## Решение по каждому рисунку

| В исходнике | Решение | Куда |
|---|---|---|
| Блоки со стрелками, процесс, конвейер | схема | `flow` |
| Слои, стек, уровни архитектуры | схема | `layers` |
| Круг, петля, цикл | схема | `cycle`; два связанных контура - `loop` |
| Матрица 2x2, квадранты | схема | `matrix` |
| Оргструктура, дерево, декомпозиция | схема | `tree` |
| Две колонки «было / стало» | схема | `compare` |
| Воронка, пирамида | схема | `funnel` |
| График с числами | данные | `curve`, `ring-bars`, `kpi`, `table` (значения в поля, не картинкой) |
| Фотография, иллюстрация настроения | фото | библиотека `assets/photos/` или тонированный файл |
| Логотипы, иконки, скриншоты интерфейсов, 3D | не переносится | смысл словами в `text`, скриншот по просьбе пользователя как `photo` после тонировки |

Схема из исходника перерисовывается по данным: читаются узлы, связи и подписи, затем заполняются поля раскладки. Если схема сложнее, чем позволяет раскладка (больше 6 узлов, два уровня связей), её делят на два слайда или упрощают до главного контура и указывают это в сообщении пользователю. Растровая вставка схемы из чужого документа запрещена: она ломает палитру и не редактируется в PPTX.

## Фотографии: три источника по убыванию приоритета

1. Библиотека `assets/photos/` - 23 кадра с единой тонировкой. Первый выбор всегда здесь.
2. Файл пользователя или кадр из исходника - два шага. Сначала `scripts/tone_photo.py in.jpg out.jpg` (файл из папки задачи или загрузок): скрипт возвращает фактический абсолютный путь в `file`, свободное имя для поля `photo` в `spec_value` и готовую пару аргументов в `build_args`, а снимок приводит к библиотечной кривой - тёплый дуотон эспрессо - карамель - слоновая кость, 18% исходного цвета, зерно; `--dark 0.25` для кадров под текст титула или раздела. Затем снимок объявляют в конкретную сборку: `build_args` передают как два отдельных аргумента, а в поле `"photo"` пишут ровно `spec_value`. Нельзя угадывать имя файла вместо возвращённого пути: имя в `--photo` всегда идёт с полным путём к выбранному файлу (для затонированного - путь из поля `file` ответа `tone_photo.py`). Путь в самой спецификации разрешения не даёт: без объявления сборка отклонит файл с кодом 5. Адреса из интернета не принимаются нигде: сборка не ходит в сеть.
3. Сгенерированное изображение - только когда библиотека не даёт нужного образа (город, интерьер, конкретный предмет) и только по промпту ниже, затем обязательно через `tone_photo.py`. Без тонировки сгенерированный кадр в деку не попадает.

## Промпт для генерации

Фиксированная рамка, в которую подставляется только объект. Промпт пишется на английском для генератора, объект берётся из содержания слайда.

```
Editorial photograph, quiet luxury, <ОБЪЕКТ: wind-shaped sand dune ridge | layered sandstone canyon wall |
silk fabric folds | brushed bronze surface | morning fog over low hills | ...>.
Warm espresso and caramel palette, soft directional light at low angle, long gentle shadows,
matte textures, shallow depth, no people, no text, no logos, no 3D render look, no neon or acid colours,
minimal composition with calm negative space in the <upper half | left third> for typography.
16:9, 2400 px wide.
```

Для вертикальной карточки (`statement`, `model`) - `4:5, 1600 px wide`. Негативные ограничения не убирать: люди, текст, логотипы и 3D противоречат системе. После генерации обязательно `tone_photo.py`, затем объявление снимка в сборку через `--photo` (см. выше) и проверка кадра в PNG рядом с библиотечными.

## Живая линия

Единственная анимация системы. Процедурная: пылевая лента из трёх прядей по пути и бегущая голова с бронзовым шлейфом, 56 кадров, 10 кадров в секунду, зацикленная. Параметры зашиты в `scripts/particle_path.py`: палитра бронза - латте - тёплый белый, запас прозрачности по краям, детерминированный seed. Где разрешена: `loop` (по умолчанию), `flow` и `cycle` (`anim: true`). В PDF попадает кадр с головой у перекрестья или на середине пути, в PPTX - GIF, который PowerPoint проигрывает в показе. В HTML GIF вшивается и играет в браузере, если сборка запущена с `--gif`; без него HTML показывает тот же неподвижный кадр.

Ограничения: только ночные слайды; до двух анимированных слайдов на деку (3-6 МБ на GIF); не рисовать линию поверх карточек. Ручная настройка не предусмотрена: другая форма пути или цвет означают новую версию скилла, а не правку в деке.
