# Самокат MCP — подключение и безопасная работа

Памятка по публичному MCP-серверу Самоката. Самокат поддерживает только пять
клиентов, перечисленных ниже; работа в других клиентах сервисом не
подтверждена. Подключение возможно только после того, как человек сам
авторизовал сервер на странице Самоката.

**Единый источник фактов:** [публичная страница Самоката](https://ai.samokat.ru/).
Команды, области доступа, названия операций и ограничения ниже взяты из неё.
Если страница изменилась — сначала перечитай её; не подставляй команды и названия
по памяти.

## Где работает

Поддерживаемые клиенты: **ГигаАгент**, **Claude Code**, **ChatGPT (веб)**,
**Codex** и **Opencode**. Ouroboros в этом списке пока нет.

Поэтому в Ouroboros это честное руководство: оно объясняет, что сделать в своём
поддерживаемом клиенте, но не выдаёт функции магазина, не хранит авторизацию и
не пересылает запросы через посредника. Не выдавай Ouroboros за Claude Code,
Codex или другой клиент, не подставляй чужой `client_id`, не настраивай
прокси/релей и не обещай «нативный Самокат в Ouroboros». Если человек уже
работает в одном из пяти поддерживаемых клиентов — веди его по инструкции
этого клиента, а не создавай второй.

## Подключение

Адрес MCP-сервера: `https://ai.samokat.ru/mcp`. Авторизация — **OAuth 2.1**
(authorization code + PKCE S256), транспорт — **Streamable HTTP, только POST, без
SSE**. Регистрация приложения и API-ключ не нужны; по правилам сервиса перед
заказом ассистент показывает итог и ждёт подтверждения человека.

| Клиент | Как подключить по документации Самоката |
|---|---|
| ГигаАгент | В каталоге «Плагины» найти «Самокат» и нажать «Подключить», затем войти и разрешить доступ. |
| Claude Code | `claude mcp add --transport http samokat https://ai.samokat.ru/mcp`, затем запустить `claude`, открыть `/mcp`, выбрать `samokat` и войти. |
| ChatGPT (веб) | В `Plugins` нажать «+», выбрать «Add custom MCP server», указать имя, адрес `https://ai.samokat.ru/mcp` и OAuth, подтвердить предупреждение и создать плагин. **Затем установить созданный плагин, открыть новый разговор и выбрать плагин через `@`** — иначе Самокат в чате не появится. По инструкции OpenAI выбор приложения относится к сообщению, где его использовали, а не ко всему разговору: уже полученный результат можно обсуждать без повторного выбора, но если продолжение требует новых данных или нового действия приложения, предложи человеку самому, если он согласен, снова упомянуть @Самокат — например, «@Самокат, да, оформи показанный заказ на этот адрес»; ассистент никогда не подтверждает от его имени. Не обещай поведение конкретной версии интерфейса: опирайся на эту инструкцию OpenAI (проверено 2026-11-21). В мобильном приложении это недоступно. По странице Самоката нужен тариф Business или Enterprise, коннектор создаёт администратор или владелец пространства (в Enterprise — по RBAC); OpenAI для своих полных MCP-возможностей указывает Business, Enterprise и Edu, а для Pro — подключение только на чтение и поиск. Условия уточняй у своего администратора. [Инструкция OpenAI](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt). |
| Codex | `codex mcp add samokat --url https://ai.samokat.ru/mcp`, затем `codex mcp login samokat`; в приложении — Settings → MCP servers → Add server. |
| Opencode | `opencode mcp add samokat --url https://ai.samokat.ru/mcp`, затем `opencode mcp auth samokat` либо `/mcps` внутри Opencode. |

При входе откроется страница Самоката: человек входит в свой аккаунт и сам
выбирает, что разрешить ассистенту. Логин, пароль, код из SMS, cookie и данные
карты в чат с ассистентом не передаются. Полный номер карты и защитный код
ассистент не видит; для выбора способа оплаты доступны только банк и
маскированный номер.

Если вход или подключение не удалось — остановись на фактической ошибке. Не
подменяй официальный сервер другой конечной точкой и не переноси авторизацию
через себя.

## Области доступа

| Область | Что разрешает |
|---|---|
| `mcp.samokat.showcase:view` | Просмотр товаров, адресов и доступных способов оплаты. |
| `mcp.samokat.address:update` | Добавление, редактирование и выбор адреса доставки. |
| `mcp.samokat.cart:update` | Просмотр и изменение корзины. |
| `mcp.samokat.cart:checkout` | Оформление заказов и изменение комментариев к адресам. |

Области независимы: бери только то, что нужно фактически запрошенной операции.

| Задача | Нужные области |
|---|---|
| Поиск товаров, состав и цены, показать адреса и способы оплаты | `showcase:view` |
| Просмотр и изменение корзины | `cart:update` |
| Оформление заказа | `cart:checkout` плюс области, чьи операции нужны для сверки перед заказом: `cart:update` (текущая корзина) и `showcase:view` (цена, адрес, способ оплаты) |
| Добавление, правка или выбор адреса | `address:update` — только когда человек этого действительно просит, не «на всякий случай» |
| Комментарий к адресу | `cart:checkout` |
| Статус заказа по известному идентификатору, отмена заказа | `cart:checkout` |

**Доступ и разрешение — разные вещи.** Область в OAuth даёт техническую
возможность; решение воспользоваться ей остаётся за человеком. Даже
`showcase:view` раскрывает адреса и способы оплаты, поэтому спрашивай, что
человеку нужно, и используй ровно эти данные: не выводи лишние адреса и способы
оплаты без запроса, не пересказывай их в другие разговоры. Лишние галочки
человек может снять при входе — это его право, а не формальность.

## Что можно делать

| Группа | Операции (область доступа по документации) |
|---|---|
| Витрина | `showcase_search_products`, `showcase_get_products`, `showcase_get_product`, `showcase_get_category`, `showcase_resolve_showcase` (`mcp.samokat.showcase:view`) |
| Корзина | `cart_get_cart`, `cart_add_to_cart`, `cart_remove_from_cart`, `cart_clear_cart` (`mcp.samokat.cart:update`) |
| Адреса, чтение | `user_addresses`, `user_address_cities`, `user_search_addresses`, `user_payment_types` (`mcp.samokat.showcase:view`) |
| Адреса, изменение | `user_add_address`, `user_select_address`, `user_update_address` (`mcp.samokat.address:update`) |
| Комментарий к адресу | `user_update_address_comment` (`mcp.samokat.cart:checkout`) |
| Заказ и его статус | `checkout_checkout_cart`, `checkout_find_checkout`, `order_find_order`, `order_tracking_get`, `order_cancel_order` (`mcp.samokat.cart:checkout`) |
| Настройки заказа по адресу | `settings_get_settings` (`mcp.samokat.showcase:view`) |

Отменить заказ через ассистента можно, пока заказ не передан курьеру; после
передачи отмена идёт через поддержку приложения.

Названия инструментов на странице — это документация. В подключённом клиенте
сначала посмотри реальный каталог и схемы; не выдумывай аргументы и не переноси
имена из одного клиента в другой без проверки.

## Правила безопасной работы

1. **Корзина общая с приложением.** Любое изменение видно человеку в
   приложении. Перечисляй фактические изменения: товар, количество, сумма.
2. **Точечное согласие не даёт права на большее.** Согласие добавить или убрать
   один товар разрешает только это действие. Отдельное явное согласие нужно на
   `cart_clear_cart`, на изменение адреса (`user_add_address`,
   `user_update_address`, `user_select_address`), на комментарий к адресу и на
   `order_cancel_order`. Чужие позиции не трогай.
3. **Личные данные и подтверждение — только владельцу аккаунта.** Состав и
   изменения корзины, суммы, способы оплаты, адреса доставки и детали заказа
   показывай только подтверждённому владельцу подключённого аккаунта и только в
   его личной сессии. В общем или групповом чате, в отчёте третьим лицам и в
   публичных сообщениях давай обезличенную публичную помощь (как подключить
   сервис, что он умеет, как отменить заказ) и не раскрывай сведений о корзине,
   адресе и деньгах. В группе не обращайся к профилю, корзине и заказам и не
   ищи «чьё-то» по имени инициатора: писать может не владелец аккаунта.
   Направляй человека в его собственный авторизованный клиент и обрабатывай
   адрес, корзину и подтверждение там.
4. **Адрес подтверждается каждый раз.** Сохранённый адрес в профиле не
   считается подтверждением. Перед заказом покажи точный текущий адрес
   доставки и спроси: «Доставляем сюда?».
5. **Оформление — только после явного «да».** Перед `checkout_checkout_cart`
   покажи лично владельцу: состав с количеством каждого товара, итоговую
   сумму, стоимость доставки и сборы (если сервер их возвращает), точный
   текущий адрес и выбранный способ оплаты — банк и маскированный номер — и
   предупреждение, что заказ настоящий и деньги спишутся с привязанной карты.
   Ответ человека должен однозначно относиться к этому конкретному заказу.
   В ChatGPT подтверждение пишет сам человек: ассистент предлагает ему,
   если он согласен, ответить с упоминанием приложения — например, «@Самокат,
   да, оформи показанный заказ на этот адрес» — и никогда не подтверждает
   заказ от его имени.
6. **Сверка перед оформлением.** Сразу перед `checkout_checkout_cart` заново
   сверь показанные поля (состав, количество, адрес, сумму, доставку и сборы,
   способ оплаты) с текущими. Если всё совпало — прежнего «да» достаточно. Если
   что-то изменилось — покажи изменения и получи новое подтверждение. Если
   сверить не удалось — не оформляй. На публичной странице Самоката атомарная
   защита от гонки не документирована — не утверждай, что сервер её не имеет;
   исходи из того, что корзина общая с приложением, а согласие относится
   ровно к показанному состоянию.
7. **Не проси и не пересылай секреты.** Логин, пароль, код из SMS, cookie,
   полный номер карты, CVV и коды 3-D Secure остаются на страницах Самоката и
   в приложении.
8. **Не повторяй оформление вслепую.** Если ответ сервера неоднозначен или
   истёк тайм-аут: в своей сессии и своём разрешении при известном
   идентификаторе проверь статус (`checkout_find_checkout` или
   `order_find_order`). Без идентификатора можно посмотреть штатные активные
   заказы (`order_tracking_get`), но один активный заказ сам по себе не
   совпадение: без привязки к этой попытке (идентификатора, времени оформления,
   состава и адреса) считать его своим нельзя. Если исход неизвестен — сообщи
   об этом прямо, повторное оформление исключено (оно может создать второй
   заказ), и предложи человеку проверить заказ в приложении.
9. **Не продлевай доступ.** Если человек просит отключить авторизацию MCP
   Самоката, передай это поддерживаемому клиенту и опиши, что именно
   подтверждено: (а) локальное состояние подключения в клиенте — плагин
   отключён или удалён; (б) отзыв доступа на стороне Самоката — только если это
   подтвердил провайдер. Локальное отключение плагина само по себе не
   подтверждает отзыв доступа у сервиса, поэтому называй только то, что видел,
   и не пытайся «обойти» отзыв доступа.

**Документированное и техническое — разные вещи.** Ограничения ниже —
это опубликованные условия сервиса, а не сбой: не обходи их повторными
попытками. И наоборот: правило «показать итог и дождаться «да»» — это правило
работы ассистента, а не техническая гарантия сервера; область `cart:checkout`
сама по себе позволяет оформить заказ, и удерживает ассистента именно показ и
согласие.

## Ограничения сервиса

По публичной странице: оплата только картой, привязанной в приложении;
баллами «Спасибо» оплатить нельзя; промокоды и история прошлых заказов
недоступны; доставка доступна туда же, куда доставляет приложение, а при
закрытом складе или остановке приёма заказов сервис сообщает об этом; нужен
аккаунт Самоката на российский номер; к одному аккаунту можно подключить до
трёх ассистентов, при подключении четвёртого отключается самый давно
неиспользуемый; сервис в бета, возможности меняются. Подключение бесплатно,
плата — только за заказы по ценам приложения для вашего адреса.

## Синтетические примеры

Все товары, цены, адреса, маски и ответы сервера в примерах вымышлены. Примеры
показывают, как вести себя, а не результат работы магазина.

### 1. Поиск без корзины

**Вопрос:** «Что взять на завтрак вдвоём до 1000 ₽?»

**Ход:** объяснить, что нужна поддерживаемая среда, где человек уже разрешил
`mcp.samokat.showcase:view`; проверить доступность витрины по его адресу,
найти товары и показать состав, КБЖУ, вес, цену и наличие из карточек,
сравнить варианты с бюджетом. Корзину не создавать и заказ не оформлять: просили
только подсказку.

**Вид ответа (все значения вымышлены):** овсянка 400 г — 189 ₽, греческий
йогурт 2%, 200 г — 149 ₽, бананы — 79 ₽; итого 417 ₽ при бюджете 1000 ₽.

### 2. Один товар в общей корзине

**Вопрос:** «Добавь в корзину бананы».

**Ход:** показать текущую корзину (только личному собеседнику) и уточнить
количество; внести точечное изменение и показать фактический результат — что
добавлено и на сколько изменилась сумма. Корзину не очищать и остальные позиции
не трогать: согласие было про один товар. Если человек просит «оформи»,
перейти к правилу 5.

**Вид ответа (все значения вымышлены):** добавлено — бананы, 1 шт., 79 ₽;
корзина 338 ₽ → 417 ₽; остальные позиции не тронуты.

### 3. Оформление заказа

**Вопрос:** «Оформи заказ на ужин до 1500 ₽».

**Ход:** собрать состав, проверить склад и доставку; показать личному
собеседнику **точное текущее** содержимое корзины с количеством каждого товара,
адрес, сумму, доставку, сборы (если возвращены) и выбранный способ оплаты;
получить явное согласие именно на этот заказ и этот адрес. Дальше — по
правилам 5–8: сверить показанные поля перед оформлением и не повторять
оформление при неизвестном исходе. Номер карты и код из SMS не просить.

**Диалог (все значения вымышлены, «Примербанк» — вымышленный банк):**

> **Ассистент:** овсянка 400 г — 2 шт. × 189 ₽ = 378 ₽; греческий йогурт 2%, 200 г —
> 1 шт. × 149 ₽ = 149 ₽; хлеб — 1 шт. × 45 ₽ = 45 ₽; товары 572 ₽, доставка 99 ₽,
> сборы 0 ₽, к оплате 671 ₽; адрес «ул. Примерная, 1»; оплата картой «Примербанк»,
> маскированный номер •••• 4242; заказ настоящий, деньги спишутся с этой карты.
> Доставляем сюда? Подтверждаете этот заказ?
>
> **Пользователь (ChatGPT):** «@Самокат, да, оформи показанный заказ на этот адрес».
>
> **Ассистент:** сверил состав, количество, адрес, сумму, доставку и способ оплаты
> с текущими — всё совпало, оформляю. Ответ сервера не пришёл: тайм-аут,
> идентификатора заказа нет.
>
> **Ассистент:** исход неизвестен. В `order_tracking_get` виден один активный
> заказ, но связать его с этой попыткой нельзя: идентификатора и времени
> оформления у меня нет, а один активный заказ сам по себе не совпадение.
> Повторно оформлять не буду — это может создать второй заказ. Проверьте заказ
> в приложении Самоката и скажите, что там видно.

### 4. Общий чат

**Вопрос в групповом чате:** «Соберите продукты к ужину и оформите».

**Ход:** в группе — только обезличенная публичная помощь: как подключить
Самокат в поддерживаемом клиенте, что сервис умеет, как отменяют заказ. К
профилю, корзине, адресам и заказам не обращаться, чужую личку по инициатору не
искать. Направь человека в его собственный авторизованный клиент: читать и
менять корзину, менять адрес и подтверждать оформление может только владелец
